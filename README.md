# Periodontal Classification -- Tooth Detection and Staging Pipeline

Automated radiographic periodontal staging from panoramic OPG images using
the 2017 Tonetti classification. The pipeline detects and numbers individual
teeth with YOLOv8-seg, then predicts periodontal bone landmarks (CEJ, apex,
bone crest) with a U-Net to compute per-tooth bone loss ratios.

## Quick-start

```bash
# 1. Install dependencies
pip install -r requirements.txt

# ── Stage A: Tooth detection ──────────────────────────────────
# 2. Convert Niihhaa LabelMe annotations to YOLO-seg format
python scripts/01_convert_labelme_to_yolo.py

# 3. Train the tooth segmentation model
python scripts/02_train_model.py

# 4. Run inference on OPG images → per-tooth crops + masks + FDI numbers
python scripts/03_run_inference.py --input data/input_opgs --output data/output

# ── Stage B: Bone landmark model ──────────────────────────────
# 5. Convert DenPAR bone-dataset annotations to heatmap training targets
python scripts/05_convert_denpar.py --vis 10

# 6. Train bone landmark U-Net (CEJ, apex, bone crest, tooth mask)
python scripts/06_train_bone_model.py

# 7. Evaluate bone model on held-out test set
python scripts/07_evaluate_bone_model.py --split test

# ── Stage C: Full staging pipeline ────────────────────────────
# 8. Run bone-model-based staging on OPG crops (replaces heuristic script 04)
python scripts/08_bone_landmark_staging.py --input periodontal_data/output --output periodontal_data/bone_staging --vis
```

## What was done

### Stage A: Tooth detection and numbering — DONE, WORKING WELL

**Dataset**: 240 OPG images from the Niihhaa dataset, converted from LabelMe to
YOLO-seg format (85/15 train/val split).

**Model**: YOLOv8m-seg trained with 5 tooth-type classes (molar, premolar,
canine, lateral incisor, central incisor).

**Results**: Detects 25-31 teeth per image at 0.87-0.94 confidence. Produces
per-tooth bounding boxes, binary segmentation masks, FDI tooth numbers (via
spatial heuristic), and expanded crops including 40% surrounding bone area.

This stage is solid and reusable.

### Stage B: Bone landmark model — DONE, FIRST VERSION TRAINED

**Problem**: The original heuristic (`bone_loss_analyzer.py`) tried to find
CEJ, apex, and bone crest from mask shape and pixel intensity. It failed
systematically — maxillary teeth reported 25-52% RBL on healthy images because
the CEJ finder broke on smooth-tapering masks and the bone threshold was
uncalibrated across different X-ray machines.

**Solution**: Train a U-Net segmentation model on the DenPAR bone-dataset to
learn anatomical landmarks directly from pixel data.

**Dataset**: DenPAR bone-dataset — 1000 periapical/intraoral radiographs:
- 650 training / 150 validation / 200 test
- Annotations per image: tooth bounding boxes, CEJ points, apex points,
  bone-crest polylines, per-tooth binary masks
- Converted to 4-channel heatmap targets via `05_convert_denpar.py`:
  CEJ circles (r=6px), apex circles (r=6px), bone-line polylines (t=4px),
  radiograph-wise tooth mask

**Architecture**: Lightweight U-Net — 1 grayscale input channel, 4 output
channels, 32 base filters, depth 4, ~7.8M parameters. Loss is Focal + Dice
combined, with bone-crest channel weighted 2x (most important for PBL).

**Training results** (80 epochs, best at epoch 54):

| Channel    | Train Dice | Val Dice | Test Dice |
|------------|-----------|----------|-----------|
| CEJ        | 0.396     | 0.314    | 0.294     |
| Apex       | 0.368     | 0.233    | 0.251     |
| Bone crest | 0.451     | 0.381    | 0.357     |
| Tooth mask | 0.942     | 0.932    | 0.942     |
| **Mean**   | **0.539** | **0.465**| **0.461** |

Tooth mask segmentation is excellent (0.94). CEJ and bone crest are reasonable
for such sparse targets (point and thin line annotations). Apex is hardest — tiny
dots with minimal spatial extent.

### Stage C: End-to-end OPG staging — DONE, FIRST RESULTS

**Script 08** connects everything: loads OPG inference output (crops + masks
from script 03), runs the bone landmark model on each crop, extracts CEJ/apex/
bone-crest positions from predicted heatmaps, computes PBL ratio, and produces
staging via the 2017 Tonetti rules.

**Comparison on 2 test OPGs (old heuristic vs new bone model):**

| Metric                | ds2_train_102 (old → new) | ds2_train_6 (old → new) |
|-----------------------|---------------------------|--------------------------|
| Stage                 | III → III                 | III → III                |
| Max RBL               | 50.0% → 28.3%            | 52.2% → 100% (1 outlier)|
| Teeth with bone loss  | 8 → 2                    | 6 → 2                   |
| Extent                | molar_incisor → localized | molar_incisor → localized|

**What improved**: The model eliminated the systematic false positives that
plagued the heuristic. The old approach reported 25-52% bone loss on 6-8 healthy
maxillary teeth per image; the new model correctly reports 0% on 29 of 31 teeth.
The noise floor dropped dramatically.

**What still fails**: A domain gap exists between DenPAR periapical images
(sharp, local, undistorted) and OPG crops (blurry, panoramic distortion, lower
resolution). On OPG crops the model fires weakly — most teeth get "No bone
crest detected" and fall back to a healthy assumption. One outlier tooth (T16)
got 100% RBL from a bad landmark fallback. The model knows the anatomy but
doesn't recognize it in a different image style.

## How to improve accuracy — next steps ranked by impact

### 1. OPG domain fine-tuning (HIGH IMPACT)

The single highest-impact improvement. The bone model learned correct anatomy
from DenPAR data but doesn't transfer well to OPG crops due to the domain gap.

**What to do:**
- Select 30-50 OPG crops from script 03 output (mix of anterior, premolar, molar)
- Manually annotate CEJ points, apex points, and bone crest lines using LabelMe
  or CVAT (takes ~2-3 hours for 50 crops)
- Convert to the same heatmap format as DenPAR
- Fine-tune the pre-trained U-Net on this small OPG set (start from `best.pt`,
  low learning rate ~1e-4, ~30 epochs)

Even 30 labeled OPG crops should dramatically improve landmark detection on OPG
crops because the model already understands the anatomy — it just needs to learn
how that anatomy looks in panoramic radiographs.

### 2. 3-tooth group crops (HIGH IMPACT)

The current pipeline crops individual teeth. Bone loss is best seen in the
**interdental** region between adjacent teeth. The DenPAR dataset itself shows
groups of 2-3 neighboring teeth per image.

**What to do:**
- Modify crop generation (script 03 or a new script) to produce group crops:
  for each target tooth, include the neighboring teeth on both sides
- Example: for tooth 36, crop the region spanning teeth 35+36+37
- This gives the bone model the interdental bone context it was trained on
- Save metadata tracking which tooth is the "target" within each group crop

### 3. Improve heatmap-to-point extraction (MEDIUM IMPACT)

The current `extract_points_from_heatmap()` and `extract_bone_crest_row()`
functions in script 08 use simple thresholding and contour centroids. Better
post-processing could help:

- **Weighted centroid**: use the heatmap values as weights instead of binary
  threshold, so the peak location is more precise
- **Per-tooth assignment**: when multiple CEJ/apex points are detected, assign
  each to the nearest tooth mask centroid instead of just closest-column matching
- **Bone crest as polyline**: instead of finding a single row, trace the bone
  heatmap as a continuous curve and find where it intersects each tooth's axis
- **Confidence filtering**: skip landmark predictions below a minimum heatmap
  peak value to avoid false positives from noise

### 4. Increase model capacity or use a pretrained encoder (MEDIUM IMPACT)

The current U-Net has 7.8M parameters trained from scratch. Alternatives:

- **ResNet-34 encoder**: use a pretrained ImageNet encoder as the U-Net backbone
  (via `segmentation_models_pytorch` library). The pretrained features for edges,
  textures, and shapes transfer well to medical imaging.
- **Increase base channels**: 32 → 64 base channels roughly 4x the parameters,
  which could help with the sparse CEJ/apex channels.
- **Multi-scale input**: feed the model crops at 2-3 different resolutions and
  fuse features, since bone crest is a large-scale structure while CEJ/apex are
  small-scale.

### 5. Better augmentation for domain transfer (MEDIUM IMPACT)

Add augmentations that simulate the OPG-to-periapical difference:

- **Gaussian blur** (sigma 1-3) to simulate OPG crop blurriness
- **Contrast reduction** to simulate the lower contrast of panoramic radiographs
- **Panoramic distortion simulation** (slight barrel/pincushion warping)
- **Random intensity gradient** across the image (panoramic X-rays often have
  uneven exposure left-to-right)

These can be added to `BoneLandmarkDataset._augment()` without any new labels.

### 6. Separate models for CEJ/apex vs bone crest (LOWER IMPACT)

CEJ and apex are point landmarks (tiny, precise). Bone crest is a line/curve
(extended, structural). Combining them in one model forces a compromise.
An alternative:

- **Model A**: U-Net predicting bone crest line + tooth mask (2 channels)
- **Model B**: Keypoint model (e.g., YOLOv8-pose) predicting CEJ + apex as
  keypoints per bounding box

This lets each model use the architecture best suited to its task.

### 7. Additional training data (LOWER IMPACT)

- **UFBA-UESC dental dataset**: OPG segmentation data that could provide
  additional tooth masks for Stage A
- **TUFTS dental database**: partially included in Niihhaa folder 3
- **Your own OPG annotations**: even a small set dramatically helps via
  fine-tuning (see step 1)

### 8. Staging rule refinements (LOWER IMPACT)

- **Confidence-weighted staging**: weight each tooth's RBL contribution by
  the landmark prediction confidence, so unreliable detections don't dominate
- **Furcation detection**: for molars, analyze the inter-root area for
  furcation involvement (a complexity factor for Stage III/IV)
- **Clinical data integration**: allow optional input of probing depths and
  clinical attachment loss to override or complement radiographic estimates

## Architecture overview

```
┌─────────────────────────────────────────────────────────────┐
│                    Full OPG image                           │
└─────────────────┬───────────────────────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────────────────────┐
│  Stage A: YOLOv8m-seg (trained on 240 Niihhaa OPGs)        │
│  → tooth bounding boxes + segmentation masks                │
│  → FDI tooth numbers via spatial heuristic                  │
│  → expanded crops (tooth + 40% bone margin)                 │
└─────────────────┬───────────────────────────────────────────┘
                  │  per-tooth crops + masks
                  ▼
┌─────────────────────────────────────────────────────────────┐
│  Stage B: U-Net bone landmark model                         │
│  (pretrained on 1000 DenPAR periapical images)              │
│  → CEJ heatmap                                              │
│  → Apex heatmap                                             │
│  → Bone crest line heatmap                                  │
│  → Tooth mask                                               │
└─────────────────┬───────────────────────────────────────────┘
                  │  predicted landmarks
                  ▼
┌─────────────────────────────────────────────────────────────┐
│  Stage C: Geometric PBL calculation                         │
│  → extract CEJ, apex, bone crest positions from heatmaps    │
│  → PBL = distance(CEJ → bone crest) / distance(CEJ → apex) │
│  → classify: ≤1/3 mild, 1/3-2/3 moderate, >2/3 severe      │
└─────────────────┬───────────────────────────────────────────┘
                  │  per-tooth RBL% and CAL(mm)
                  ▼
┌─────────────────────────────────────────────────────────────┐
│  Stage D: 2017 Tonetti staging rules                        │
│  → severity from max CAL + RBL                              │
│  → tooth loss from missing FDI numbers                      │
│  → complexity from vertical defects                         │
│  → extent: localized / generalized / molar-incisor          │
│  → final stage = max(severity, tooth loss, complexity)       │
└─────────────────────────────────────────────────────────────┘
```

**Training data sources:**
- **Dataset A (Niihhaa)**: 240 full OPGs → tooth segmentation + numbering
- **Dataset B (DenPAR)**: 1000 periapical X-rays → CEJ/apex/bone-crest landmarks

## Honest assessment

**What works well:**
- Tooth detection, segmentation, and FDI numbering are reliable
- The bone landmark model learned correct anatomy on periapical data
- The model-based approach eliminated systematic false positives from the heuristic
- The staging rules correctly implement the 2017 framework
- The end-to-end pipeline runs and produces structured output

**What doesn't work well yet:**
- Domain gap between periapical training data and OPG inference crops
- Landmark detection fires weakly on OPG crops (most teeth fall back to defaults)
- One outlier tooth produced 100% RBL from bad fallback geometry
- Apex detection is the weakest channel (0.25 test Dice) due to tiny target size

**What would make it accurate:**
- Fine-tuning on 30-50 manually labeled OPG crops (the single biggest improvement)
- Group crops to show interdental bone context
- Better augmentation to simulate the periapical-to-OPG appearance shift

The foundation is solid. The gap between "promising prototype" and "clinically
useful tool" is primarily a data problem (domain mismatch), not an architecture
problem. The model understands the anatomy — it just needs to see it in the right
image modality.
