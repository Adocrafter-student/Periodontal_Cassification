# Periodontal Classification -- Tooth Detection and Staging Pipeline

Train a YOLOv8-seg model on the Niihhaa dental OPG dataset to detect, segment,
and number individual teeth, then produce expanded tooth+bone crops for
downstream radiographic periodontal staging (2017 Tonetti classification).

## Quick-start

```bash
# 1. Install dependencies
pip install -r requirements.txt

# 2. Convert Niihhaa LabelMe annotations to YOLO-seg format
python scripts/01_convert_labelme_to_yolo.py

# 3. Train the model (add --batch 2 for 8 GB GPUs)
python scripts/02_train_model.py

# 4. Run inference on new OPG images
python scripts/03_run_inference.py --input data/input_opgs --output data/output

# 5. Convert DenPAR bone-dataset annotations to training masks
python scripts/05_convert_denpar.py --vis 10

# 6. Train bone landmark U-Net
python scripts/06_train_bone_model.py

# 7. Evaluate bone model visually
python scripts/07_evaluate_bone_model.py --split test

# 8. Run periodontal staging on inference output
python scripts/04_periodontal_staging.py --input data/output --output data/staging
```

## Current status

### Step 1-2: Data conversion and training -- DONE

- 240 images converted from LabelMe to YOLO-seg format (85/15 train/val split).
- YOLOv8m-seg trained on the Niihhaa dataset with 5 tooth-type classes
  (molar, premolar, canine, lateral incisor, central incisor).

### Step 3: Tooth detection, segmentation, and numbering -- WORKING WELL

Produces for every OPG image:
- Per-tooth bounding boxes and segmentation masks
- FDI tooth numbers via spatial heuristic (quadrant + sort by distance from midline)
- Expanded crops (tooth + 40% surrounding bone area)
- Structured JSON with all metadata

Tested on example OPGs and detects 25-31 teeth per image with high confidence
(0.87-0.94). Crops and masks are clean and usable.

### Step 4: Periodontal staging (2017 classification) -- HEURISTIC VERSION, BEING REPLACED

The heuristic `bone_loss_analyzer.py` had fundamental accuracy problems (inflated
RBL on maxillary teeth, CEJ detection failures on molars, uncalibrated bone
thresholds). This is being replaced by a learned bone-landmark model (Steps 5-7).

### Step 5-7: Bone landmark model -- IN PROGRESS

**New approach**: Instead of heuristic intensity analysis, train a U-Net on the
DenPAR bone-dataset (1000 periapical X-rays with annotated CEJ, apex, and
bone-crest landmarks) to predict these landmarks as heatmaps.

**Dataset**: DenPAR bone-dataset with 1000 images:
- 650 training / 150 validation / 200 test
- Per image: bounding boxes, CEJ points, apex points, bone-crest polylines,
  per-tooth binary masks

**Pipeline**:
1. `05_convert_denpar.py` converts JSON annotations to heatmap masks
2. `06_train_bone_model.py` trains a 4-channel U-Net (CEJ, apex, bone-line, tooth)
3. `07_evaluate_bone_model.py` produces visual overlays for quality inspection

**Architecture**: Lightweight U-Net (32 base channels, depth 4, ~2M parameters)
with Focal + Dice combined loss. Bone-crest channel weighted 2x because it is
the most critical output for PBL ratio calculation.

**Domain gap**: DenPAR images are periapical/intraoral style, not panoramic OPGs.
The model serves as bone-landmark pretraining; fine-tuning on 30-50 labeled OPG
crops may be needed for optimal OPG performance.

1. Run `05_convert_denpar.py` to generate training masks from DenPAR annotations
2. Run `06_train_bone_model.py` to train the U-Net
3. Run `07_evaluate_bone_model.py` to visually inspect predictions
4. If predictions look reasonable, proceed to OPG integration

### NEXT -- Generate 3-tooth group crops from OPGs

Instead of single-tooth crops, generate group crops containing the target tooth
plus its left and right neighbors. This provides inter-dental bone context that
is critical for bone-crest detection.

### NEXT -- Build model-based bone loss calculator

Replace `bone_loss_analyzer.py` with a new module that:
1. Runs the trained U-Net on each group crop
2. Extracts CEJ, apex, and bone-crest positions from predicted heatmaps
3. Computes PBL ratio per tooth geometrically
4. Returns `ToothAnalysis` objects compatible with existing staging code

### LATER -- OPG domain fine-tuning

The DenPAR model sees periapical images. For OPG crops, fine-tune on 30-50
manually annotated OPG group crops to bridge the domain gap.

### LOWER IMPACT -- Additional refinements

- **Furcation detection** for Stage III/IV complexity factors
- **Confidence-weighted staging** to reduce edge-detection noise
- **Clinical data integration** for optional probing depth / CAL overrides

## Summary of the pipeline vision

```
STAGE A (working):
  OPG image  -->  [YOLOv8-seg]  -->  per-tooth masks + FDI numbers

STAGE B (in progress):
  DenPAR dataset  -->  [05_convert]  -->  heatmap targets
  heatmap targets  -->  [06_train U-Net]  -->  bone landmark model

TARGET PIPELINE:
  OPG  -->  [YOLOv8-seg]  -->  tooth masks + FDI numbers
                                    |
                              3-tooth group crops
                                    |
                            [U-Net bone model]
                                    |
                          CEJ + apex + bone crest
                                    |
                              PBL ratio per tooth
                                    |
                            2017 Tonetti staging
```

Two training data sources:
- **Dataset A (Niihhaa)**: Full OPG → tooth segmentation + FDI numbering (done)
- **Dataset B (DenPAR)**: Periapical X-rays → CEJ/apex/bone-crest landmarks (in progress)

The bone landmark model is the missing piece that replaces the fragile heuristic
bone loss analyzer with learned anatomical features.
